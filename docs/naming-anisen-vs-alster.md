# Именование: «Альстер» больше не существует — есть ANISEN и ANISEN Финанс

Зафиксировано со слов Ольги 14.09.2026. Это важно для всех будущих сессий и агентов, чтобы не путать два разных продукта под одним именем.

## Суть решения

Раньше было финансовое приложение (Telegram Mini App) под названием «Альстер». Оно переименовано в ANISEN (в контексте финансового приложения — «ANISEN Финанс» / «Анисен Финанс»). Названия «Альстер» как бренда/продукта больше не существует нигде — ни в самом приложении, ни в общении с пользователями, ни в новых материалах.

Теперь есть два разных продукта под общим именем ANISEN, и их важно не путать:

1. ANISEN (сайт услуг) — anisen.ru, статический сайт-визитка Ольги как эксперта по продажам (отдел продаж под ключ, внешний РОП, аудит, amoCRM, прозвон и т.д.). Репозиторий olganja2025/My-Sale-Site.
2. 2. ANISEN Финанс (бывший «Альстер») — финансовое Telegram Mini App приложение. Бэкенд/бот/фронтенд на том же сервере, в директории /root/alster (название директории и имена контейнеров — alster-bot-1, alster-backend-1, alster-frontend-1 — остались от старого названия, это чисто техническая, невидимая пользователю деталь, трогать не обязательно).
  
   3. ## Что с доменом
  
   4. Домен alster-os.ru / api.alster-os.ru пока остаётся как есть — Ольга сознательно не хочет сейчас возиться с переносом на поддомен или новый домен под ANISEN, пока приложением пользуется только она сама. То есть: снаружи (в браузере, в ссылке из Telegram-бота) домен всё ещё называется alster-os.ru, но по сути и по названию это уже ANISEN Финанс, а не «Альстер». В будущем (не сейчас, сроков нет) возможен перенос на какой-то домен/поддомен под брендом ANISEN — решение не принято, обсудим отдельно, когда дойдёт очередь.
  
   5. ## Практический вывод для будущей работы
  
   6. - В переписке, документах и коде не использовать слово «Альстер» как название продукта — только «ANISEN» и «ANISEN Финанс» (или «Анисен» / «Анисен Финанс» по-русски), когда речь о финансовом приложении.
      - - Слово «alster» в путях на сервере (/root/alster, имена контейнеров, docker-сеть alster_default) — это унаследованное техническое имя инфраструктуры, не смысловая ошибка. Менять это прямо сейчас не обязательно, но при удобном случае можно постепенно уйти и от этого — не срочно.
        - - Технически ANISEN (сайт услуг) и ANISEN Финанс — это два совершенно разных продукта, разный код, разные репозитории, разные аудитории. Их разделили ещё и на уровне серверной инфраструктуры 14.09.2026 — подробности ниже.

          ## Техническая часть: разделение серверной инфраструктуры (14.09.2026)

          ### Почему это понадобилось

          13.09.2026 сайт anisen.ru упал (ERR_SSL_PROTOCOL_ERROR) из-за того, что оба продукта — ANISEN (сайт услуг) и ANISEN Финанс (бывший Альстер) — работали через один и тот же общий reverse-proxy (Caddy), который физически жил внутри директории /root/alster и настраивался её же docker-compose файлом. Когда поддержка Timeweb вмешивалась в работу ANISEN Финанс (пересоздавала контейнер Caddy), это ломало и anisen.ru тоже, хотя это два независимых продукта. Решение — физически развести Caddy на два независимых друг от друга контура, чтобы работа над одним продуктом больше не могла случайно уронить другой.

          ### Что сделано

          Создана новая, полностью самостоятельная директория /root/anisen-edge (сервер Timeweb, "Intelligent Snipe", IP 104.171.137.123), не имеющая отношения к /root/alster. В ней:

          - Caddyfile — конфиг со всеми тремя доменными блоками (alster-os.ru, api.alster-os.ru, anisen.ru/www.anisen.ru).
          - - docker-compose.yml — описывает только один сервис caddy (образ caddy:2-alpine), с портами 80:80/443:443 и томом /srv/anisen:/srv/anisen:ro для раздачи статики ANISEN. Подключён к внешней docker-сети alster_default (networks: alster_default: external: true) — то есть видит контейнеры backend/frontend ANISEN Финанс и может проксировать на них трафик, но сам не входит в состав их docker-compose проекта.
           
            - Старый сервис caddy: внутри /root/alster/docker-compose.yml — остановлен, удалён как контейнер (docker compose stop caddy && docker compose rm -f caddy) и полностью вычищен из самого файла (строки блока caddy: удалены). Теперь /root/alster/docker-compose.yml описывает только сервисы backend, bot, frontend — про Caddy там больше ничего нет, значит обычный docker compose up -d внутри этой папки никогда больше не попытается поднять свой Caddy и столкнуться портами с независимым.
           
            - Новый независимый Caddy запущен (cd /root/anisen-edge && docker compose up -d), контейнер называется anisen-edge-caddy-1. Проверено: оба домена (anisen.ru и alster-os.ru) отвечают корректно, автоматическое управление TLS-сертификатами Let's Encrypt работает для всех доменов.
           
            - ### Итоговая схема (после 14.09.2026)
           
            - - /root/alster/ — только сама ANISEN Финанс: backend, bot, frontend. Своего Caddy/reverse-proxy больше не содержит.
              - - /root/anisen-edge/ — независимый reverse-proxy (Caddy), обслуживает оба продукта: раздаёт статику ANISEN (сайт услуг) напрямую из /srv/anisen и проксирует ANISEN Финанс через docker-сеть alster_default.
                - - Референсный/резервный экземпляр правильного Caddyfile также лежит вне обеих папок, в /tmp/Caddyfile.anisen (переживает перезагрузки не гарантированно, т.к. /tmp — это резервная копия для восстановления, не источник истины; источник истины теперь — /root/anisen-edge/Caddyfile).
                 
                  - ### Что это значит для любого агента (включая «Кодекс»), который будет работать над ANISEN Финанс
                 
                  - - Перезапуск, пересборка или любые манипуляции с контейнерами внутри /root/alster больше не затрагивают anisen.ru — можно спокойно останавливать/пересобирать backend, bot, frontend, не опасаясь уронить сайт услуг.
                    - - Не добавляйте обратно сервис caddy: в /root/alster/docker-compose.yml — это разрушит сделанное разделение и может привести к конфликту портов 80/443 с независимым Caddy в /root/anisen-edge.
                      - - Если нужно поменять маршрутизацию/домены ANISEN Финанс (например, добавить новый домен или поддомен) — редактировать нужно /root/anisen-edge/Caddyfile (не файл внутри /root/alster), и после изменений выполнить docker exec anisen-edge-caddy-1 caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile.
                        - - Директория /root/alster по-прежнему называется так исторически (см. раздел про именование выше) — сама программа официально называется ANISEN Финанс.
