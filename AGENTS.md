# ALSTER — постоянные правила сайта

Этот файл является обязательной инструкцией для любых изменений сайта ALSTER.

Перед началом ЛЮБОЙ задачи по этому репозиторию сначала прочитать AGENTS.md и соблюдать его.

Если конкретное задание пользователя конфликтует с AGENTS.md, прямое указание пользователя в текущей задаче имеет приоритет.

Если прямого указания изменить существующий стандарт нет — стандарт из AGENTS.md сохраняется.

Главный принцип:

НЕ ПЕРЕИЗОБРЕТАТЬ уже утверждённые элементы сайта.

Если компонент, стиль или паттерн уже существует и утверждён, необходимо переиспользовать его, а не создавать новый вариант.

==================================================

30. ЕДИНАЯ НИЖНЯЯ ЧАСТЬ ПРОДУКТОВЫХ СТРАНИЦ
==================================================

Для всех страниц услуг используется единая логика нижней части страницы:

основной контент → реальные кейсы → стоимость → FAQ → финальные переходы / CTA → Footer.

Блок «Стоимость» располагается перед FAQ.

Блок FAQ / «Частые вопросы» располагается в конце содержательной части страницы перед финальной навигацией / CTA и Footer.

Страница «Отдел продаж с нуля» является визуальным эталоном блока стоимости. На других страницах услуг переиспользовать его дизайн и компонент, меняя только содержание.

Не переставлять эти блоки на отдельных страницах без прямого указания пользователя.

==================================================
31. ЕДИНЫЙ ПЕРВЫЙ ЭКРАН ПРОДУКТОВЫХ СТРАНИЦ
==================================================

Первый экран каждой страницы услуги строится по одному утверждённому шаблону.

Слева:

– H1 – название услуги;
– короткий подзаголовок / объяснение;
– при необходимости короткий дополнительный текст;
– основной CTA в утверждённом стиле сайта.

Справа:

– единая информационная карточка 2×2 из четырёх параметров:

Срок проекта / Старт
Формат
Подход
Результат

Конкретное название первого параметра может зависеть от услуги, например «Срок проекта» или «Старт». Остальные параметры также могут содержательно адаптироваться, если это действительно требуется смыслом услуги, но структура из четырёх характеристик сохраняется.

Эталоном первого экрана является утверждённый первый экран страницы «Отдел продаж с нуля».

На остальных страницах переиспользовать его:

– композицию;
– пропорции левой и правой частей;
– ширину контента;
– положение H1;
– размер H1;
– типографику подзаголовка и текста;
– положение и стиль CTA;
– размеры и положение правой карточки;
– сетку карточки 2×2;
– внутренние отступы;
– радиусы;
– цвета;
– типографику подписей и значений;
– адаптивное поведение.

Не создавать индивидуальный Hero для каждой услуги.

Разница между страницами должна быть прежде всего в содержании, а не в конструкции первого экрана.

Если название услуги длинное, НЕ увеличивать и НЕ уменьшать H1 относительно эталона. Использовать нормальный перенос строк.

Если текст в правой карточке длиннее, адаптировать формулировку текста, а не растягивать карточку и не менять размер шрифта.

Не добавлять в Hero без прямого указания:

– цену;
– дополнительные бейджи;
– декоративные номера;
– новые плашки;
– рукописные записки;
– изображения;
– новые CTA;
– дополнительные колонки.

Главная страница остаётся эталоном глобальной типографики сайта, а «Отдел продаж с нуля» – эталоном конструкции первого экрана продуктовой страницы.

Не переделывать автоматически все Hero сайта. Конкретные страницы приводить к стандарту по отдельным заданиям.

Правило текста в информационной карточке Hero 2×2:

– в каждой из четырёх ячеек есть подпись параметра и самостоятельное значение;
– значение ВСЕГДА начинается с заглавной буквы, независимо от визуального расположения;
– подпись и значение воспринимаются как два отдельных текстовых уровня;
– значение не является грамматическим продолжением подписи после двоеточия.

Правильно:

СРОК ПРОЕКТА
От 2 месяцев

ФОРМАТ
Проект веду лично

ПОДХОД
Под конкретный бизнес

РЕЗУЛЬТАТ
Готовый к работе отдел продаж

Это постоянное правило единого компонента Hero 2×2 для всех продуктовых страниц.
1. ОБЩАЯ КОНЦЕПЦИЯ ALSTER
==================================================

ALSTER — серьёзный сервисный B2B-бренд, но сайт не должен выглядеть как типовой стерильный сайт консалтинговой компании.

Характер сайта:

— профессиональный;
— спокойный;
— структурный;
— человеческий;
— уверенный;
— практичный;
— без корпоративного пафоса;
— без визуального шума;
— без ощущения шаблонного консалтинга.

Сайт должен сочетать два слоя:

1. Основной интерфейс:
строгий, чистый, минималистичный, структурный.

2. Личный слой:
небольшие рукописные комментарии Ольги, которые иногда добавляют живую человеческую ремарку к официальному тексту.

Принцип:

«Сайт рассказывает официально → Ольга иногда добавляет от себя».

Не превращать сайт:
— в корпоративный портал;
— в технологический SaaS;
— в агрессивный маркетинговый лендинг;
— в набор ярких рекламных карточек;
— в стерильный консалтинг;
— в слишком мужской индустриальный дизайн.

2. ГЛАВНЫЕ ЭТАЛОНЫ
==================================================

ГЛАВНАЯ СТРАНИЦА является эталоном общей дизайн-системы сайта.

По ней определяются:

— типографика;
— размеры H1;
— размеры H2;
— основной текст;
— подписи;
— кнопки;
— базовые отступы;
— визуальный ритм;
— общий характер карточек;
— цвета;
— плотность интерфейса.

Внутренние страницы НЕ должны самостоятельно вводить новые размеры шрифтов или новые стилистические правила.

КЕЙС «СТРОЙБЫТ» является эталоном оформления реальных кейсов.

Все следующие реальные кейсы должны использовать его структуру и визуальную логику.

Существующие согласованные переходы между услугами на ГЛАВНОЙ СТРАНИЦЕ являются эталоном для аналогичных переходов на внутренних страницах.

Если аналогичный элемент уже существует на главной странице — сначала переиспользовать его.

==================================================
3. ЦВЕТОВАЯ СИСТЕМА
==================================================

Основная палитра ALSTER:

— тёплый молочный / off-white фон;
— спокойный sage / шалфейный зелёный;
— основной зелёный ориентировочно #698477;
— глубокий зелёно-графитовый ориентировочно #4D675C;
— тёмный графит для основного текста и контрастных элементов;
— серо-бежевые и молочные оттенки для вторичных поверхностей.

Акцентные зелёные оттенки должны быть приглушёнными.

НЕ использовать:
— кислотный лайм;
— неоновый зелёный;
— яркие жёлтые Post-it;
— случайные новые акцентные цвета;
— чистый агрессивный чёрный в больших тяжёлых массивах, если можно использовать глубокий графит;
— градиенты без прямого указания.

Если используется зелёная подложка/свечение/смещение за карточкой, оно должно быть спокойным и приглушённым.

Цвет не должен перетягивать внимание с содержания.

4. ТИПОГРАФИКА
==================================================

Основной шрифт сайта:
Manrope.

Рукописные ремарки:
Caveat.

Главная страница — эталон размеров типографики.

Обязательные правила:

— H1 одного уровня на всех продуктовых страницах имеет одинаковый размер;
— H2 одного уровня на всех страницах имеет одинаковый размер;
— основной текст одного уровня имеет одинаковый размер;
— eyebrow / подписи имеют единый размер;
— кнопки имеют единую типографику.

НЕ создавать индивидуальный font-size только потому, что конкретный заголовок длиннее или короче.

Если заголовок не помещается:
1. проверить ширину контейнера;
2. использовать нормальный перенос строки;
3. адаптировать композицию;
4. НЕ менять типографический уровень страницы.

Не делать огромные H1 на внутренних страницах.

Не уменьшать текст отдельных карточек только ради того, чтобы он поместился.

Сначала сохраняется дизайн-система, затем внутри неё адаптируется контент.

==================================================
5. СТРУКТУРА ПРОДУКТОВЫХ СТРАНИЦ
==================================================

Все страницы услуг должны восприниматься как части одного сайта.

Они не обязаны иметь абсолютно одинаковый контент или количество секций, но одинаковые по функции элементы должны выглядеть одинаково.

Типовая логика продуктовой страницы:

— единый Header;
— первый экран;
— при необходимости информационная плашка услуги;
— проблема / ситуации клиента;
— объяснение подхода;
— состав или содержание работы;
— результат;
— внедрение / процесс, если необходимо;
— реальные кейсы;
— стоимость;
— FAQ, если нужен;
— переходы к связанным услугам;
— CTA;
— единый Footer.

Не добавлять секции только ради соблюдения шаблона, если они не нужны конкретной услуге.

Но если одинаковая секция существует на нескольких страницах, она должна использовать одну визуальную систему.

==================================================
6. ПЕРВЫЙ ЭКРАН ПРОДУКТОВЫХ СТРАНИЦ
==================================================

Первый экран должен быстро объяснять:

— что это за услуга;
— для кого / в какой ситуации;
— в чём основной смысл;
— какое следующее действие доступно посетителю.

Не перегружать первый экран перечислениями.

Не повторять на первом экране содержание следующих секций.

H1 — по эталону главной страницы.

CTA — в существующей системе кнопок.

Не добавлять декоративные элементы на первый экран без согласования.

==================================================
7. ИНФОРМАЦИОННАЯ ПЛАШКА УСЛУГИ 2×2
==================================================

Для продуктовых страниц используется единый компонент информационной плашки 2×2.

Это ОДИН компонент с разным содержимым.

Не создавать отдельный дизайн плашки для каждой услуги.

Параметры:

— сетка 2×2;
— одинаковая геометрия;
— одинаковые размеры;
— одинаковые радиусы;
— одинаковая типографика;
— глубокий графитовый / зелёно-графитовый фон;
— спокойный приглушённый зелёный акцент;
— без кислотного лайма;
— без тяжёлого неонового свечения.

Плашка не должна визуально конкурировать с H1.

В плашку НЕ выводить стоимость услуги на первом экране.

Цена раскрывается ниже по странице после того, как посетитель понял содержание и ценность услуги.

Содержимое четырёх ячеек адаптируется под конкретный продукт.

Если текст не помещается:
адаптировать текст, а НЕ увеличивать компонент и НЕ уменьшать произвольно шрифт.

==================================================
8. КАРТОЧКИ
==================================================

Карточки сайта должны использовать единую визуальную систему.

Общие параметры:

— спокойный светлый фон;
— существующие радиусы;
— единая типографика;
— аккуратные внутренние отступы;
— минимум декоративных эффектов;
— никаких случайных теней и новых цветов;
— одинаковые карточки одной группы имеют согласованную геометрию.

Карточки не должны быть неоправданно высокими.

Не оставлять большие пустые белые зоны только ради одинаковой фиксированной высоты.

Если используется сетка 2×2:
— карточки внутри одной строки могут иметь одинаковую высоту;
— высота должна определяться реальным содержанием;
— не использовать чрезмерный min-height;
— сохранять плотный и аккуратный вертикальный ритм.

Не уменьшать шрифт ради заполнения пространства.

Не растягивать карточку без причины.

==================================================
9. РУКОПИСНЫЕ РЕМАРКИ ОЛЬГИ
==================================================

Рукописные ремарки — важная часть характера ALSTER, но используются дозированно.

Шрифт:
Caveat.

Визуальный характер:

— небольшая записка;
— лёгкий естественный наклон;
— молочный, серо-бежевый или приглушённый зелёный фон;
— оттенки только из общей палитры сайта;
— ощущение заметки на полях;
— не яркий классический Post-it.

Текст:
— короткий;
— человеческий;
— иногда ироничный;
— от первого лица или как личная ремарка;
— не повторяет основной текст;
— добавляет дополнительную мысль или характер.

НЕ использовать записку как обязательный элемент каждой секции.

НЕ добавлять рукописные заметки автоматически.

НЕ создавать бессмысленные декоративные подписи:
— «Отдел продаж 01»;
— «Продажи 02»;
— номера секций;
— псевдотехнические маркировки.

Если записки не было в утверждённом блоке — не добавлять её без указания.

Одна секция обычно не должна содержать больше одной такой ремарки.

==================================================
10. РЕАЛЬНЫЕ КЕЙСЫ
==================================================

«СтройБыт» — визуальный эталон.

Все реальные кейсы сайта оформляются по ОДНОМУ шаблону.

Структура:

МАРКИРОВКА
«Реальный кейс»

НАЗВАНИЕ
Название клиента / проекта.

ПАСПОРТ ПРОЕКТА
В существующей зоне, аналогичной «СтройБыту»:

— сфера;
— регион, если известен;
— срок работы, если известен.

Не выдумывать отсутствующие данные.
Если параметр неизвестен — не показывать его.

ОСНОВНАЯ СТРУКТУРА

«Была задача»

«Что сделали»

«Стало»

Именно эти формулировки использовать как стандарт.

Не заменять:
— «Что сделали» на «Что выяснили»;
— «Была задача» на произвольные варианты;
— «Стало» на длинные маркетинговые заголовки.

Тексты кейса должны быть короткими.

Не превращать кейс в подробную хронологию проекта.

Логика:
проблема → действие → результат.

==================================================
11. ОТЗЫВЫ В РЕАЛЬНЫХ КЕЙСАХ
==================================================

Если у кейса есть реальный отзыв, использовать настоящий скрин/фотографию отзыва.

Не перепечатывать отзыв вместо скрина, если задача предусматривает графический отзыв.

Не генерировать отзывы.
Не создавать фейковые Telegram-скриншоты.

Зона отзыва является частью единого шаблона кейса.

Если реальный скрин ещё не получен:
— сохранить геометрию и структуру места под него;
— не растягивать текст кейса на освободившееся пространство;
— не удалять колонку/область отзыва;
— не менять шаблон кейса.

При этом посетителю НЕ показывать:
— «отзыв скоро»;
— пустую техническую рамку с подписью;
— фейковую заглушку.

После получения изображения его должно быть возможно добавить без переделки всей секции.

==================================================
12. ПЕРЕХОДЫ МЕЖДУ УСЛУГАМИ
==================================================

На главной странице уже существует утверждённый формат переходов между услугами.

Он является эталоном.

На внутренних страницах не создавать новые виды:
— стрелочных карточек;
— баннеров;
— кнопок-переходов;
— навигационных плиток.

Если нужно связать услугу с другой услугой:
использовать существующий паттерн главной страницы.

Сохранять:
— типографику;
— геометрию;
— отступы;
— радиусы;
— цветовую логику;
— hover;
— стрелки/индикаторы.

Меняется только содержание.

==================================================
13. КНОПКИ И CTA
==================================================

Использовать существующую систему кнопок сайта.

Не создавать новый размер кнопки для отдельной страницы.

Одинаковые CTA должны иметь:
— одинаковую высоту;
— одинаковые внутренние отступы;
— одинаковый радиус;
— одинаковый размер текста;
— одинаковую логику hover.

Перед созданием новой кнопки проверить, существует ли уже аналогичная.

Если существует — переиспользовать её.

==================================================
14. HEADER
==================================================

Header должен быть единым на всех страницах.

Не создавать отдельный header для конкретной услуги.

Не менять:
— навигацию;
— размеры;
— отступы;
— CTA;
— расположение элементов;
без прямого указания.

Логотип ALSTER должен отображаться одинаково на всех страницах.

Новый мастер-логотип пока НЕ утверждён.

До отдельного решения использовать существующий ранее согласованный графический вариант логотипа.

Не заменять его самовольно просто текстом ALSTER.

Не создавать временные новые логотипы.

==================================================
15. FOOTER
==================================================

Footer является общим компонентом сайта.

Не создавать разные footer для отдельных услуг.

Не менять его при работе с контентной секцией страницы.

==================================================

Разовая услуга – одна конкретная самостоятельная задача: скрипт, мотивация, настройка CRM, отчётность, найм одного сотрудника и т. д.

Минимальная стоимость комплексной доработки – от 50 000 р.

Для разовых услуг аудит не обязателен. Разовая задача продаётся отдельно по своему прайсу и может стоить дороже в пересчёте на одну задачу, чем аналогичная работа внутри комплексного проекта.

Причину разницы в цене не расписывать клиенту длинным объяснением. Достаточно показать понятный отдельный прайс.

Страница «Отдел продаж с нуля» остаётся визуальным эталоном блока стоимости, но содержание её цены позже приводится к этому же стандарту прозрачности.

В рамках локальной задачи не менять цены и содержание других продуктовых страниц.
